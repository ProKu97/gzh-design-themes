# 输入归一化 —— 排版流程只认 Markdown

不管用户给的是什么格式，第一步永远是把它转成 Markdown 草稿，**经人确认结构之后**才进入 SKILL.md 第 1 步选主题。这一步只整理结构（标题层级、列表、图片位置），**不许增删或改写原文的实质内容**。

## 先判断输入是什么

| 拿到的东西 | 怎么认出来 | 怎么处理 |
|---|---|---|
| Markdown | `.md` 后缀，或正文本身带 `#`/`##`/`![]()` 这类标记 | 直接进流程（先按下面的 gotcha 清掉剪存元信息） |
| Word | `.docx` 后缀 | 跑 `scripts/extract_docx.py`（见下） |
| PDF | `.pdf` 后缀 | 用 Read 工具逐页读 + 按下面的清噪规则处理 |
| 纯文本 | `.txt`，或粘贴过来的一大段没有任何标记的文字 | 靠语义推断结构（见下） |
| 网页/富文本 | 带 HTML 标签，或能看出剪贴板样式的残留 | 剥掉样式，按语义映射成 Markdown |
| 老版 `.doc` | 后缀是 `.doc` | 解析不了，请用户先在 Word/WPS 里另存成 `.docx` |

## Word（.docx）

```bash
<SKILL_ROOT>/scripts/extract_docx.py 文章.docx -o 文章.md
```

这个脚本不依赖任何第三方库：标题样式对应到 `#`–`######`，粗体对应 `**`，下划线对应 `<u>`，列表对应 `- `，正文里嵌的图片会解包到输出文件旁边的 `images/` 目录、用相对路径引用。表格会转成 Markdown 表格；遇到解析不了的结构会在终端里提示。跑完之后，把生成的 `.md` 读进来，照常走下面的结构确认。

## PDF

用 Read 工具直接按页读（PDF 是原生支持的），读完之后按这几条清一遍噪声：

1. **去页眉页脚**：每页都重复出现的同一行（书名/章节名/网址）、纯页码行（`12`、`- 12 -`、`Page 12`）。
2. **把被断开的句子接回去**：一行结尾没有句末标点（。！？；：）、下一行又是小写字母或中文续着写的，说明是排版造成的硬换行，要拼成一段；结尾有标点的保留分段。
3. **找标题**：PDF 读不到原始字号信息，只能靠下面纯文本那套启发式规则判断。
4. **处理图表**：PDF 里的插图没法直接提取，原位置留一个"【配图：原文第 N 页插图】"占位（最终会渲染成居中的待补板块）。
5. 双栏排版的 PDF 常见的问题是两栏内容被读串了行——如果发现上下句衔接不上，提醒用户这份 PDF 可能需要人工先理一遍。

## 纯文本 / 无标记粘贴 —— 靠语义猜结构

**判断一行是不是标题，看这几条，占得越多越可信**：

- 这一行很短（20 字以内），而且结尾不是句末标点（。！？）
- 前后都是空行，或者正好在全文/一段话的开头
- 带编号前缀，比如"一、""二、""1.""01""第 X 章/节/部分""Part N"
- 整体节奏是"一行短的后面跟好几段长的"

**分出层级**：全文里出现频率最高的那种标题模式定为 `##`；如果还有更细一级的，定为 `###`；开头单独那一行孤立短句定为 `#` 全文标题。

**整篇都找不出任何标题特征时**：按内容的语义把全文切成 3~6 个板块，给每块自己拟一个不超过 12 字的小标题（标题要讲人话、贴着这段内容走，不要写"第一部分"这种空壳词），并且在后面的结构确认里明确告诉用户"这几个标题是我自己加的"。

其余对应关系：空行就是分段；带引号的句子或后面跟着破折号署名的，当作开头引言的候选；`1. 2. 3.` 或者 `·`/`-` 开头的连续几行，当作列表。

## 网页 / 富文本

`<h1>`–`<h6>` 对应到相应级别的 `#`，`<strong>`/`<b>` 对应 `**`，`<img src="...">` 对应 `![](原地址)`（外链地址原样留着），`<li>` 对应 `- `，`<blockquote>` 对应 `> `；样式属性、多余的 `<span>` 嵌套、`&nbsp;` 这类垃圾标记全部去掉。剪藏工具自己加的那段元信息（原文链接、剪藏时间、工具署名）不是正文的一部分，连同一起去掉。

## 结构确认（默认必须做，只有全自动模式才跳过）

归一化做完、还没选主题之前，把推断出来的结构给用户看一眼确认：

> 识别出 N 个章节：01 xxx / 02 xxx / ……（其中第 3、5 个标题是我自己加的）。图片 M 张。这个结构对吗？

这一步只花十几秒，但省下来的是排错了整篇重做的成本——结构认错了，后面全排错。用户确认或改完之后，再进选主题那一步。

## 全自动模式（用户给了纯文本、还说了"直接排"）

用户说"直接排""自动排""一键排版""不用问我"，或者明显就是想直接拿结果时：

1. 跳过结构确认和选主题的提问，整条链路自动跑完：推断结构 → 按题材从 `theme-index.md` 里自己挑最贴的主题 → 排版 → 校验。
2. 交付时要**附一段决策说明**——不是在征求同意，是让用户能审查你做了哪些判断：识别出的章节结构、哪些标题是自己拟的、选了什么主题、为什么选这个。
3. 用户对某个决策不满意，按那一点改就行（换主题重排、调整章节切法），不用整篇推倒重来。

全自动模式下没有明显题材倾向时，默认主题按 `theme-index.md`「选择建议」走——目前是品牌深蓝·蓝图。
