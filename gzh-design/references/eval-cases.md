# 回归用例 —— 触发判断 · 主题选择 · 排版质量

每次动了 `SKILL.md` 的 description、加了新主题、或改了选主题的路由逻辑，照这份清单过一遍，确认"该触发的还触发、不该触发的没触发、主题推荐依然合理"。

## 该触发 gzh-design 的说法

- "帮我把这篇 Markdown 做成公众号排版"
- "微信公众号文章排版"
- "用 XX 主题排这篇"（XX 是 `theme-index.md` 里已登记的主题名）
- "把下面这篇文章转成能直接粘进公众号编辑器的 HTML"
- "这篇文章帮我排个版，发公众号用"
- "给公众号排版生成一套新主题/自定义风格"（→ 走自定义主题生成流程）
- "照这张参考图帮我做一套公众号排版组件库"（→ 走自定义主题生成流程）

## 不该触发、应该转给别的能力的说法

- "帮我做一个网页落地页" → 前端/网页类 skill
- "把内容做成 PPT" → PPT 类 skill
- "帮我排版这个 Word 文档" → 排版对象不是公众号文章
- "写一篇公众号文章" → 这是写作任务，不是排版（得先有文章，再轮到本 skill）

## 选主题这件事该怎么做

- 用户点名了 `theme-index.md` 里已登记的主题 → 直接用，不用再问。
- 题材和某个主题明显对得上 → 只问一句"建议用 XX（理由），确认还是换一套？"，选项给推荐项 + 1~2 个备选 + "看全部"，不要替用户定死。
- 题材看不出明显倾向 → 默认把 `theme-index.md` 第一行（目前是品牌深蓝·蓝图）作为推荐项放第一位，让用户在几套里挑。
- 用户明说"直接排/一键/不用问" → 这是唯一的例外，自动选题材最贴的主题，交付时说明理由。
- 用户选定主题之后 → 进入该主题内部，按"文章类型 → 组件组合配方"表匹配组件，不是随手挑。
- `theme-index.md` 是空的（没有任何已登记主题）→ 不要凭记忆编一套主题出来，告诉用户需要先添加主题风格。

## 排版质量核对清单（拿一篇含代码块和图片的真实文章跑一遍）

- [ ] 选主题时默认把 `theme-index.md` 第一行放在推荐位
- [ ] 解析完结构先判断了文章类型，再按该主题"文章类型 → 组件组合配方"表选组件（不是逐段随手挑）
- [ ] 点缀组件的种类数没有超过配方表规定的上限
- [ ] 正文自然段相邻时 `margin-bottom:0`；段落后面紧跟小标题时改成 `8px`；小标题本身不再叠加顶部空隙
- [ ] 生成的弯引号、全角标点在写出来那一刻就是对的，不是事后替换
- [ ] 代码/命令走代码块组件，没有被塞进普通段落
- [ ] 图片走图片组件；是动图的话加了"GIF"角标
- [ ] 正文里没有残留半角标点（代码块内部除外，那里要保持原样）
- [ ] 开头引言卡的署名跟着文章的作者或主题走，没有写死某一个具体的人名
- [ ] 结尾签名区默认用 `{{作者名}}` 占位；用户给了署名才填进去；原文本来就有签名段就直接沿用原文
- [ ] 原文已经带了签名段时，合并进唯一的那个签名区，没有重复出现两处
- [ ] 强调和小标题用的是左竖条或小标签，没有用四周虚线框
- [ ] 代码块足够紧凑：每行一个 `<p style="margin:0">`，没有用 `white-space:pre`，没有大片空白
- [ ] "【插入……】"这类待补占位用的是居中板块，不是左对齐的提示条
- [ ] 骨架是按所选主题自己的"完整文章模板骨架"装配的，没有套别的主题的骨架
- [ ] 生成完之后跑过 `scripts/validate_gzh_html.py`，没有 ERROR，也没有半角标点的 WARNING

## 自定义主题生成这条路该怎么验

- 用户只给了一句风格描述就说"生成新主题" → 一次性把偏好字段问全，不逐字段追问；空着的字段按 `theme-generator.md` 的规则自动补全。
- 用户上传了参考图 → 先用 Read 工具提取视觉特征，只做风格转译，不照抄图里的文字/Logo/具体构图。
- 生成的区块库存到 `assets/theme-previews/{主题ID}.html`，所有区块连续排在一个页面里，用户一次性浏览整页确认风格（不是逐块展示逐块确认），确认后再转成正式主题库。
- 转换成 `theme-{标识}.md` 时：补上 `<span leaf="">`、去掉预览阶段用的 `id`、补齐五个必备部分（设计变量表/组件/骨架/配方表/映射表）。
- 新主题要登记进 `theme-index.md`，并且 `component_lint.py` 跑出 0 ERROR 才算交付完成；交付之后"列出全部主题给用户选"这一步必须包含它。
- 主题 ID 和已有的撞车了 → 提醒用户换个名字或者确认要不要覆盖，不能静默覆盖掉已有的。

## 不同输入格式该怎么验

- 给一份 `.docx` → 先跑 `scripts/extract_docx.py` 转成 Markdown，再走结构确认，不要直接当文本读二进制文件。
- 给一份 `.pdf` → 用 Read 逐页读，删掉页眉页脚和页码，把硬换行断开的句子接回去，插图位置留一个居中占位。
- 给一段没有任何标记的 `.txt`（但里面有"一、二、"这种编号）→ 正确识别成 `##` 级标题，确认过结构再排版。
- 给一段完全没有标题痕迹的纯文本，并且说"直接排" → 走全自动模式：按语义分章、自己拟标题、自选主题，交付时附一段决策说明。
- 给一份老版 `.doc` → 提醒用户先另存成 `.docx`，不要强行解析。

## 维护时的可验证闭环

改了组件库、`SKILL.md` 或脚本之后，按这个闭环走一遍，确保没有带进新的排版反模式（大片空白、左对齐占位块、正文里出现虚线框、碰到平台禁用项）：

1. **改**：组件库 / SKILL.md / 脚本。
2. **过源头关**：`python3 scripts/component_lint.py .`，扫描所有组件库里的 ```html 代码块，检查有没有 `white-space:pre`（会造成大片空白）、四周虚线框 `border:…dashed`（居中的待补占位块除外）、以及各类平台禁用项（`<div>`/`class`/`id`/`<style>`/`display:grid`/`position:fixed`等/CSS 变量/`@media`）。必须 **0 ERROR**。
3. **生成**：用改完的 skill 排一篇真实文章（或任意一段测试稿）。
4. **过产物关**：`python3 scripts/validate_gzh_html.py <生成的.html>`，检查禁用标签、`<span leaf="">` 包裹是否齐全、半角标点有没有混进来。必须 **0 ERROR，半角标点 0 WARNING**。
5. 只要有一关没过，回到第 1 步修，直到两关都绿。

两个脚本分工不同：`component_lint.py` 管"组件库这个源头本身干不干净"，`validate_gzh_html.py` 管"最终排出来的产物合不合规"。源头干净了，产物自然跟着干净——这是这套闭环成立的道理。
